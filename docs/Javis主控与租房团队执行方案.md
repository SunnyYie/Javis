# Javis 主控与租房团队执行方案

日期：2026-11-10

状态：设计文档，尚未实施。本文描述目标架构、接入约束、迁移顺序和验收标准，不代表相关能力已经可用。

## 1. 目标与范围

将 Javis 从求职专用助手扩展为可调度多个专业 Agent Team 的个人助手：

- Brain-Leader 负责理解需求、选择团队、协调依赖、保存任务进度和汇总结果。
- 求职业务归属 Career Team，主控不再实现简历、岗位匹配、面试和学习计划等业务。
- 新增 Rental Team，完成需求确认、房源搜索、通勤查询、成本与风险比较、候选房源清单及看房检查清单。
- 房源仅从唯果 MCP、自如 MCP 获取，按“唯果优先、自如补充”的顺序执行，不接入其他房源平台、通用网页搜索或第三方房源清单。
- 支持跨团队任务，例如“选定工作地点后，帮我找通勤合适的房子”，但跨领域信息共享需要用户确认。
- 保留既有 `bl` 命令、配置、历史会话和求职流程，新增 `javis` 入口。

本次交付仅为本文档。后续实施不包含联系中介、发送预约、支付、签约、自动提交个人信息，也不新增 Web 前端或常驻后台服务。

## 2. 当前结构与调整原因

当前 `Brain-Leader` 是终端求职 Agent，而不是通用主控：

| 位置 | 当前职责 | 目标归属 |
| --- | --- | --- |
| `Brain-Leader/src/brain_leader/agent.py` | 求职提示词、领域工具、聊天与面试分流 | 通用路由留主控；求职 Agent 与工具归 Career Team |
| `Brain-Leader/src/brain_leader/service.py` | 求职流程编排及状态操作 | 求职服务归 Career Team |
| `Brain-Leader/src/brain_leader/resume.py`、`interview.py` | 简历与模拟面试业务 | Career Team |
| `Brain-Leader/src/brain_leader/cli.py` | 命令、授权、导出及交互 | 保留兼容门面；领域命令转发给相应团队 |
| `Brain-Leader/src/brain_leader/storage.py` | 会话、消息、记录与记忆 | 原数据保留；增加任务映射与领域隔离 |
| `tools/src/javis_tools/adapters.py` | 现有助手适配与调用隔离 | 保留已工作的适配方式，逐步收敛职责 |

特别需要处理：当前等待面试回答时，自然语言会优先进入答案提交逻辑。通用助手必须先识别明确的切换意图，再征求用户同意暂停，不能把“帮我找房”直接记录成面试答案。

## 3. 目标架构

```text
用户 / 终端
    |
Javis / Brain-Leader
    |-- 意图识别、澄清、任务依赖、授权请求、状态汇总
    |
    |-- Career Team
    |     |-- Career Leader
    |     |-- Job-Agent
    |     |-- Interview-Question-Bank
    |     `-- Knowledge-Assistant
    |
    `-- Rental Team
          |-- Rental Leader
          |-- Search Agent
          |     |-- 唯果 MCP（优先）
          |     `-- 自如 MCP（补充）
          |-- Location / Commute Agent -> 高德路线服务
          `-- Cost / Risk Agent -> 费用计算与有依据的风险分析
```

### 3.1 主控边界

主控可以：

- 查看静态注册的团队能力、获取脱敏的团队状态。
- 将任务交给团队、查看进度、请求取消或暂停、汇总团队结果。
- 对跨团队任务建立依赖，例如先确认办公地点，再开始通勤筛选。
- 向用户请求补充信息或授权。

主控不可以：

- 直接调用简历生成、面试评分、房源页面解析等领域工具。
- 复制一份团队提示词和领域业务作为“快捷处理”。
- 自动获得子团队全部文件、历史记录、密钥或浏览器会话。
- 通过扫描目录自动授予插件执行权限。

团队能力采用显式注册表。技能文档提供操作指导，不等同于可执行插件或授权。

### 3.2 Rental Team 内部分工

| 角色 | 输入 | 责任 | 输出 |
| --- | --- | --- | --- |
| Rental Leader | 已确认需求、用户补充、任务状态 | 分解任务、调度专家、检查约束覆盖、生成最终比较 | 搜索进度、候选清单、待确认事项 |
| Search Agent | 城市、预算、租赁方式、区域等条件 | 通过受限 MCP 适配器搜索、读取详情、保存来源证据 | 标准化房源与各来源执行状态 |
| Location / Commute Agent | 房源位置、已授权目的地、出行方式 | 地点消歧、高德真实路线查询、比较通勤条件 | 查询时间、路线、耗时、换乘及不确定项 |
| Cost / Risk Agent | 房源证据、租期、费用条款 | 确定性费用计算、缺项检查、合同及看房风险提示 | 成本分解、证据引用、待核验问题 |

专家需要有真实、可追踪的任务调用和结果边界，不能只在单次回答中写几个角色标题。租金和费用算术由程序完成；模型负责解释，不能自行补齐未知费用。

## 4. 调度协议与任务状态

复用现有结果信封字段：`status`、`data`、`citations`、`warnings`、`artifacts`、`error`。

新增中立的团队调用契约，至少包含：

| 对象 | 必要字段 |
| --- | --- |
| 团队能力 | `team_id`、能力说明、输入约束、授权需求 |
| 任务请求 | `task_id`、`parent_task_id`、`session_id`、`team_id`、目标、结构化约束、授权上下文引用、预算 |
| 任务结果 | 原结果信封、子任务引用、来源覆盖情况、待用户操作 |
| 持久化任务 | 状态、依赖、需求版本、确认版本、授权记录、检查点引用 |

将“执行进度”和“结果质量”分开：

- 执行进度：排队、执行中、等待用户、已暂停、已完成、已取消。
- 结果质量：`ok`、`partial`、`blocked`、`failed`。
- 等待登录、地址消歧或确认时，应明确给出 `pending_action`，不能用一条普通警告掩盖。
- MCP 返回经验证的零结果才是有效的空结果；鉴权失败、配额耗尽、登录页、验证码、拦截页和解析失败都不是零房源。
- 有可用房源但部分请求来源不可用，返回 `partial` 并列出缺失来源；全部来源被阻断则返回 `blocked`；技术故障导致全部不可用则返回 `failed`。混合失败也要保留逐来源原因。

跨团队场景只传递用户确认过的最小摘要。例如求职团队输出“已确认办公目的地及位置引用”，不传完整简历、薪资记录或面试文本。用户未选定的岗位不能被当作租房通勤目的地。

## 5. 房源数据源选择与验证现状

唯一房源来源为唯果 MCP、自如 MCP。默认按此顺序分别查询并合并候选，唯果结果优先展示，自如用于补充覆盖和比较；不会因为某个来源失败而接入第三个平台。用户主动限制为其中一个来源时，仅在该明确范围内报告覆盖情况。

来源不可用时只在剩余来源中继续查找，并报告 `partial` 及原因；两个来源都不可用时返回 `blocked` 或 `failed`。不静默放宽预算、城市等硬条件，不把未查询的来源写成已覆盖。

以下为本轮实际测试记录，不是未来实施后的验收结果。

| 来源 | 已验证情况 | 当前结论 |
| --- | --- | --- |
| 唯果 vigolive MCP | HTTPS 端点初始化成功，返回服务版本 `2.13.0.2`，列出 7 个工具；无 Key 搜索明确返回 `X-API-Key header is required` | MCP 可达且工具契约已发现；缺少专用 Key，真实房源、详情及费用字段尚未验证 |
| 自如 `playwright_with_ziroom` | MCP 初始化、列出 11 个工具、创建武汉会话、搜索、应用 1500–2200 元条件、最终条件校验成功；详情读取时价格图片请求超时 | 搜索链路部分可用，详情与费用完整性未通过 |

自如离线测试为 11 通过、1 失败、3 跳过；失败涉及状态版本冲突错误信息被 MCP 包装，不能宣称测试全通过。唯果“真实在线直租房源”目前为平台声明，尚未完成带 Key 抽样核验。

### 5.1 唯果接入

通过标准 MCP 客户端连接 `https://mcp.vigolive.cn/mcp/`，使用 `X-API-Key` 请求头鉴权，不依赖网页爬虫或浏览器登录。

用户在微信 vigolive 小程序“我的”页面查找“AI 接入”或“MCP 连接”，生成 Javis 专用 Key。Key 保存在本地受保护配置或凭据管理器中，仅交给唯果适配器，不进入提示词、聊天、日志或 Git。

执行规则：

1. 启动时检查鉴权配置、初始化和工具 schema；缺少 Key 时返回 `blocked` 与配置指引，不进入无效搜索重试。
2. 使用 `search_houses` 按已确认城市、预算、租赁方式等条件获取候选，再用返回的 `house_id` 调用 `get_house_detail`，不臆造 ID。
3. `search_by_commute` 仅作为候选初筛；其工具描述为估算通勤时间，不能替代高德真实路线查询证据。
4. 只向 Search Agent 暴露房源搜索、详情和通勤初筛三个工具。`evaluate_house`、`verify_house`、`query_knowledge` 不作为房源或结论的替代来源；成本与风险仍由本项目专家根据证据处理。
5. 不调用 `get_contact_qrcode`，不联系房东或管家，维持仅搜索与决策的范围。
6. 请求及响应均经字段白名单处理；费用缺失、位置模糊、字段冲突和挂牌时效不足必须保留，不能由模型补齐。
7. 拒绝鉴权、超配额、限流和超时分别记录原因。来源错误不能被解释成零房源，也不能通过轮换 Key 绕过额度。

平台说明主要覆盖北京、上海、深圳、广州、杭州等城市，但实际库存及其他城市覆盖需带 Key 验证。某城市无房源不等于整个平台不可用。

免费额度存在文档冲突：仓库 README 写 30 次/天/key，`docs/api-key.md` 写 500 次/天/key，且配额统计口径也有矛盾。以账号后台、实际响应和平台确认信息为准；未核实前不承诺高额度，不按多个 Key 累加预算。搜索、详情和通勤初筛均计入本地调用预算，不能把“免费”解释为无限调用。

验收必须至少完成一次带 Key 的真实搜索及详情读取，核对返回房源 ID、租金单位、位置、费用、更新时间与平台内可查看信息。初始化成功、工具列出成功不等同于房源获取成功。

### 5.2 自如接入

优先独立启动现有 MCP server，通过标准客户端调用，不直接复制第三方业务代码进 Javis。

执行规则：

1. 使用真实 Playwright 后端；macOS 明确配置 Chrome 路径。
2. 创建搜索会话，通过动态 schema 获取可用筛选项，不臆造选项编码。
3. 每次修改携带当前 `session_id` 和 `state_version`，使用响应中的新版本。
4. 地点、区域、地铁等互斥条件按实际 schema 处理。
5. 修改造成空结果时按服务协议恢复检查点；响应已自动恢复时，不重复恢复。
6. 最终调用 `get_results(expected_filters=...)` 检查条件是否真正生效。
7. 单条详情失败保留列表证据，并将详情字段标记未知，不编造价格、押金或服务费。
8. 在 `finally` 中关闭搜索会话。

服务端浏览器状态保存在内存，重启后用已确认需求重新创建会话，不继续使用旧会话 ID 和版本号。

当前测试依赖组合包含 MCP 2.3.0、Playwright 1.65.0。实施时先验证并锁定兼容版本，不无条件使用 `latest`，也不通过放宽断言掩盖第三方兼容失败。

自如浏览器使用项目独立会话，不读取个人 Chrome 的用户目录或 Cookie。确需用户登录时，在独立会话中人工完成；持久化登录状态需另行确认，并纳入删除范围。

不向领域 Agent 暴露任意 JavaScript 或 Shell，不扩展成通用浏览器控制。页面内容和 MCP 返回文本均为不可信数据，不能提升为指令或授权。浏览器跳转和网络访问限于自如业务所需域名及明确依赖，域名限制不能只依赖单个工具参数。

遇到安全拦截、验证码、禁止访问或限流时停止该来源，不通过代理、伪装、换 IP 或切换浏览器工具绕过限制。

### 5.3 访问预算与资源释放

建议初始默认上限：每个来源每次任务 1 页、最多 10 条列表、最多 3 条详情。唯果每任务最多 5 次业务工具调用（1 次搜索、3 次详情、按需 1 次通勤初筛），且不能超过已核实的剩余日配额；配额未核实时本地按不超过 30 次/天保守限额，实际更低时以平台为准。

同来源串行调用，请求间隔至少 3 秒，并遵守平台更严格的限制。浏览器操作、远程 MCP 请求均设置超时和任务总时限；子任务继承同一访问预算，不能通过再次委派重置计数。

鉴权失败、配额耗尽、登录失败、验证码、拦截与限流不自动重试；普通暂时故障最多一次有界重试，重试也计入预算。任务取消或异常退出时关闭客户端连接，并释放本地自如 MCP 进程和浏览器资源，不对远程唯果服务执行停机操作。

## 6. 租房决策流程与证据模型

### 6.1 需求确认

先收集城市、月租预算、整租/合租、入住时间，以及用户提出的户型、区域、宠物等硬条件。预算需区分“仅租金”与“含已知固定月费”。

用户提出通勤要求时，再确认目的地、出行方式和可接受时长；未提供通勤需求时，不强制索取精确工作地址。

输出结构化需求供用户确认。需求变更后生成新版本，使旧搜索授权范围或旧比较结论显式失效；不能把旧结果直接包装成满足新条件的结果。

### 6.2 房源记录

每条房源至少保存：

- 来源（仅 `vigolive` 或 `ziroom`）、房源 ID、平台提供的链接（若有）、采集时间及快照 ID；没有链接时以来源及房源 ID 追踪，不拼造链接。
- 列表标题、城市/区域、位置精度、租赁方式、面积、户型和已知配套。
- 租金数值及计价单位、押付方式、固定费用、一次性费用、最短租期。
- 已应用的筛选条件与验证结果、列表/详情读取状态。
- 每项关键结论的 MCP 响应字段或有界页面证据、未知项及冲突项。

实时 MCP 结果与历史 MCP 快照使用不同新鲜度标记；快照只能追溯到上述两个来源，保留采集时间和过期提示，不作为当前仍可出租的保证。不新增其他平台链接解析、网页搜索或房源清单导入入口。

优先按平台房源 ID 和规范化链接去重；同小区或相似标题不能直接合并成同一套房。跨平台疑似重复只标注关联，并保留原始来源。

### 6.3 通勤查询

使用项目独立的高德凭据与真实路线接口，不依赖本次 Codex 环境已有工具作为部署前提。密钥仅交给地图适配器，不传主控、模型或其他平台。

地点歧义先由用户确认；坐标记录坐标系，高德坐标按 GCJ-02 处理，不能混用坐标系。精确位置只在已授权的必要环节传递，向模型提供尽可能粗粒度的摘要。

默认公共交通，有其他需求则按用户选择查询。保存查询时间、模式、路线和返回耗时；返回值是路线服务估算，不承诺实际早晚高峰必然相同。缺少凭据、地址或授权时明确标记“未查询”，不得生成看似真实的通勤分钟数。

唯果返回的估算通勤时间单独标记为平台初筛值，不覆盖高德查询结果。高德仅提供位置与路线，不作为第三个房源来源。

### 6.4 成本与风险比较

分开列示：

- 每月持续支出：租金、明确收取的固定管理费等。
- 一次性不可退支出：已明确的中介费、服务费等。
- 可退押金：作为资金占用，不直接计入消费成本。
- 首次付款现金：按已知押付方式计算首期租金、押金及费用。

已知租期成本 = 已知月度支出 × 租期月数 + 已知一次性不可退费用。存在缺项时只能称为“已知部分成本”，并注明未含项目；未知值不按 0 处理。水电等按实际使用结算的项目不伪造固定金额。

比较表同时展示硬条件是否满足、数据缺口、通勤状态、成本覆盖程度和采集时间。默认不生成无法解释的总分；资料不足的房源单独列出。

风险结论区分“来源明确说明”“需要看房核验”“一般合同注意事项”。没有证据不能认定房源虚假、无风险或合同合法。最终给出少量候选、选择依据、缺失信息和看房核验清单，不替用户完成交易决策。

## 7. 会话、隐私与兼容迁移

### 7.1 数据边界

- 既有职业数据库路径、会话 ID 和记录引用先保持不变，避免直接重建或整体搬迁。
- 主控新增任务与领域会话映射；Rental Team 使用独立存储位置。
- 长期记忆增加领域作用域和授权范围。旧职业记忆默认归 `career`，不自动共享为所有团队可见。
- 原隐私处理会去除地址字段；租房位置需要专门的授权与脱敏策略，不能直接照搬导致位置丢失，也不能因此关闭全部隐私保护。
- 浏览器状态、截图、页面文本可能含敏感信息；按任务最小保存、设置保留期，日志不记录凭据或完整 Cookie。
- 文件导入、跨域共享、长期记忆确认、导出与删除保留宿主侧人工控制，模型不能自行确认授权。

### 7.2 代码迁移方式

未来建议增加 `agents/Career-Team` 与 `agents/Rental-Team`，通用团队契约放在不依赖任何领域团队的中立模块。依赖方向为“主控 -> 团队 -> 共享能力”，不得形成“团队 -> 主控 -> 团队”的环。

现有求职调用先通过兼容门面转发，再逐步移走业务实现。旧导入路径在兼容期只做转发，不维护第二份业务。不能简单把整个旧 service 挂到主控旁边后就宣称完成职责拆分。

保留已有 SQLite 工作线程所有权、上下文追踪、文件锁和适配器清理逻辑。`bl daily` 的独立流程保持行为不变，不顺带重构。

### 7.3 命令与迁移安全

`bl` 保持原有求职命令语义；`javis` 进入通用会话，新领域控制使用明确命名空间，避免覆盖原 `/confirm`、`/status` 等语义。

数据库变化必须有版本号、迁移前备份和明确回滚流程。先用复制的历史库验收，迁移需可重复运行、保持原记录引用，并验证失败不会留下半迁移状态。回滚前检测是否已有新写入，不能直接恢复旧备份覆盖用户新增数据。

面试切换流程：

1. 识别明确的跨领域请求，询问用户是否暂停面试并切换。
2. 未同意前不创建新的已授权租房任务；拒绝则回到原题。
3. 同意后保存当前题目、回答状态和恢复令牌，不提交切换文本为答案。
4. 模糊输入先澄清，不直接提交答案或切换领域。
5. 返回求职时恢复同一道题，暂停期间不提前展示答案或复盘内容。
