# AI Agent 每日一题

独立的技术学习模块，不使用职业画像、简历、会话历史或作答记录。
默认按北京时间周一至周五 11:00 运行，不自动计算法定节假日或调休。
收到的是一道题、答案、细分领域，以及最多三篇相关技术文章。
答案要点分别附知识库原始资料链接，延伸阅读独立联网搜索、读取正文后筛选。

## 配置

复制模板 `.env.daily.example` 为本地 `.env.daily`，填入：

```dotenv
BL_DAILY_ENABLED=true
BL_DAILY_APP_ID=填写应用ID
BL_DAILY_APP_SECRET=填写私有凭证
BL_DAILY_RECIPIENT_EMAIL=填写收件邮箱
BL_DAILY_WEB_SEARCH=true
```

私有配置须设为 `0600`，已被 Git 忽略。不要把凭证放进定时任务提示词、
命令参数、截图、文档或提交记录。已在聊天中提供的 Secret 建议在部署完成后轮换，
然后只更新本地配置。普通 `bl doctor` 不验证飞书；显式 `probe` 才调用认证接口。

飞书应用须开启机器人能力、发布可用版本，并具备发送消息所需的权限
（例如 `im:message:send_as_bot`）。收件人必须处于应用可用范围。
邮箱直接作为该应用的 `receive_id`，不借用其他应用的 `open_id`，
也不需要把联系人邀请链接保存在程序中。
认证通过不等于具备发送权限，首次发送回执才验证实际消息接口。

## 命令

在本项目目录运行：

```bash
.venv/bin/bl daily status
.venv/bin/bl daily schedule
.venv/bin/bl daily probe
.venv/bin/bl daily preview --allow-remote
.venv/bin/bl daily run --allow-remote
```

`preview` 生成并冻结当日题，不发送；可通过 `--day YYYY-MM-DD` 预生成指定日期。
已有题目直接读取，不重复调用模型。`run` 只处理北京时间当天，早于 11:00、
周末或 `BL_DAILY_ENABLED=false` 时跳过，不补发历史日期。
`--allow-remote` 是本次技术资料模型处理/推送的显式许可，不继承职业会话的授权。
使用现有模型配置，每个新题生成、核验各调用一次模型；
联网获得文章正文后再调用一次模型筛选，另有原有有限结构化重试。

题目只来自五个大类：RAG、LangChain、Harness engineering、Claude Code底层实现、
Multi-Agent。按北京时间周一至周日划分周次，每周使用系统随机源把五类洗牌一次，
分别安排到周一至周五；每类每周最多一次，不固定为用户提供的排列顺序。
顺序保存在 SQLite 的 `daily_weekly_topics`，重启、预览、失败重试不会重新抽签。
`bl daily schedule` 可离线查看并固定本周顺序，`--day YYYY-MM-DD` 可指定另一周；
查看排期不生成题目、不发送消息。不同周独立洗牌，可能偶然出现相同顺序，不刻意排除。
成功发送以及发送结果不确定的同类题都会阻止本周另一日再发；明确失败时保留当日类别，
只允许原有安全重试流程，不换大类凑题。仍不跨日补发或在周末补齐漏发类别。
旧发送回执不改写；已冻结但与新排期冲突的未发送题会报错，不偷偷换题或重复发送。
Claude Code 只考察公开文档或公开代码可证实的机制，不将未公开实现推断当作事实。
同一题目的规范化标题不能与最近 60 条保存记录重复；这不是语义去重保证。

## 证据与内容

复用知识助手的原有检索、Embedding、向量索引和 Reranker，在原专用线程运行。
答案只取现存知识片段，不调用其回答保存流程、不向公共库写入生成答案或联网文章。
片段需有未过期的时间、HTTPS 链接，且来源标识与链接符合中性技术内容规则。
检索前后核对语料 ID 和版本，变化时失败，不混用不同版本片段。
不能与独立知识助手同时操作同一个知识目录。

主模型生成结构化题目和答案；程序验证引用 ID、逐字原文摘录，再独立调用模型
逐项核验答案支持度与主题相关性。答案链接只由检索结果构造，不能由模型杜撰。
题干优先一到两句、聚焦单一问题，答案优先2到4个要点；模型正文不允许嵌入 URL。
发出前对整个消息（包括标题、标签、链接）检查中文职业相关词及对应英文、
编码和零宽字符。来源不足、已过期、重复题、非法引用、核验失败或敏感内容都不发送，
不为了凑题绕过检查。模型核验和关键词检查并非形式化正确性或完备语义审查。
延伸阅读复用知识助手现有搜索服务和授权配置；不复制搜索 Key，不额外读取账号信息。
最多查询5个搜索结果，每页读取上限1 MiB、连接/读取超时12秒、最多3次重定向，
复用已有 DNS 固定与私网访问阻断。网页必须有真实标题和至少200字正文；
仓库主页、文章列表页、搜索摘要或访问验证页都不作为推荐依据。
文章选择限制为最多3篇，优先2到3篇；推荐理由须附可核对的正文摘录，摘录只存本地。
标题、理由和 URL 继续过敏感内容检查，卡片中的外部文本作 Markdown/HTML 转义。
缺少搜索凭证、网络失败或仅一篇相关时，返回真实阅读数量与机器可读警告，
不虚构文章凑数；`BL_DAILY_WEB_SEARCH=false` 可关闭联网阅读。

卡片使用 Card 2.0：大字号加粗题目、浅色问题区域、常规字号分点答案、
小字号逐项来源及独立阅读区。除题目、答案、来源、文章外不添加验证声明、
库名括注或宣传尾句。没有服务端交互回调，链接直接跳转。
带连续编号的小问单独成段：主干保留大字号加粗，小问使用常规字号，
只加粗编号，不改写原题。支持半角/全角括号编号及独立行的数字列表；
非连续、缺失内容或歧义编号保留原样，不将函数参数、版本号误作小问。

所有自动 LangSmith 正文追踪保持关闭；模型仅接收技术主题、原始知识片段、
近期技术题标题，不接收飞书凭证或账号邮箱。飞书 token 仅保存在进程内存。

## 发送与恢复

本地状态在 `BL_DATA_DIR/daily/daily.sqlite3`，文件 `0600`、新目录 `0700`，
保存不可变题目、来源快照、语料版本、发送 UUID、状态及消息 ID，不保存凭证。
整个 CLI 复用 `.leader.lock`，避免和主应用并行访问同一运行目录。

- `prepared`：已冻结内容，尚未发送。
- `sending`：已持久化发送意图；进程崩溃后不自动重发。
- `sent`：飞书返回 `message_id`；同日重跑直接跳过。
- `rejected`：接口明确拒绝；排查权限/应用范围后，可手动 `run --allow-remote --retry-rejected`。
- `unknown`：超时、服务端错误或不完整回执；消息可能已送达，不自动重发。

发送前取得 token；鉴权失败不写入发送意图，下次可以安全重试。
每次消息使用持久化固定 UUID，辅以飞书短期幂等保护；该保护不能替代本地长期状态。
不跟随 HTTP 重定向、不自动重试发送、不回显 token 或原始飞书错误正文。
CLI 错误只给内部分类和数值 `vendor_code`，以便核对权限问题。
收件人变化后已有发送记录的当天不会自动发给新收件人。

当天旧消息已经发送而用户明确要求调整格式时，可以预览、再发送一次修订卡片：

```bash
.venv/bin/bl daily restyle --allow-remote
.venv/bin/bl daily restyle --allow-remote --send
```

这不会重新生成原题或答案，不会删除原回执。修订在同一私有数据库的
`daily_card_v2` 表中保存，有独立 UUID 和发送幂等保护；再次执行不重复发送。
如未发送的修订还需调整，可显式 `restyle --allow-remote --rebuild`；
旧预览快照先归档到 `daily_card_history`，再生成新预览，不覆盖已发送内容。
已发送、发送中或不确定状态不允许重建。日常定时任务不调用该人工修订命令。

仅调整排版、无需重新搜索或新增消息时，使用：

```bash
.venv/bin/bl daily refresh --allow-remote
```

优先更新当天已发送的 Card 2.0 修订，否则更新当天原卡片。只使用原有题目、
答案和文章快照，不调用模型；通过飞书 PATCH 更新同一消息。
更新意图与结果单独追加到 `daily_layout_updates`，保留原发送快照和回执。
接口失败不自动重试，也不退回到发送新消息；普通定时任务不调用此命令。

若确认实际已收到但本地状态为 `sending/unknown`，可人工登记消息 ID：

```bash
.venv/bin/bl daily acknowledge YYYY-MM-DD om_实际消息ID --confirm-received
```

不要删除数据库来“重试”，这会丢失去重依据。没有确认收到时应先在飞书查证。
`sent` 只代表飞书接口返回有效消息 ID，不声称用户已阅读。

## 调度

本模块提供一次性 `daily run`，不启动常驻 Web 或后台服务。
本任务通过 Codex 的工作日 11:00 定时跟进调用该命令，凭证始终读取本地配置，
不会写入定时提示词。可在 Codex 自动化中暂停或调整。
需要本机和 Codex 运行、网络及现有知识服务可用；睡眠或离线不能保证准点，
不把“定时配置成功”称为“下一次已准时送达”。同日延迟触发可发送，跨日不补发。
部署到独立服务器时可用其受管调度器执行同一个命令，但不要重复开启两套调度。
