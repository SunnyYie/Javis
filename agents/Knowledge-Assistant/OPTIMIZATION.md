# 检索覆盖优化与真实复验

日期：2026-11-05，Asia/Shanghai。问答与评估模型仍为 `glm-5.3-flashx`。

清理说明：按用户后续要求，旧轮次原始输出及所有隔离测试库已删除。
本文保留清理前的执行过程、指标与失败结论；历史路径仅用于标识当时运行。
最新 E2E 记录及两组最终评估的回答、分数、环境和报告仍保留，见 `data/acceptance/README.md`。

## 本轮改动

1. 两路各最多召回 20 条，默认将 RRF 的完整去重并集、最多 40 条交给重排，
   不再默认在 32 条处丢掉单路召回的尾部材料。最终证据仍最多 8 条。
2. 同一来源、commit、目录默认优先主 `README.md`，避免多语言重复简介占据名额。
   显式指定其他语言文件时尊重指定；没有主 README 时保留现有版本；
   `README_POLICY=all` 可关闭策略。没有删除或重新嵌入任何原文。
3. 召回与重排都保留独立问题的完整要求，去掉将问题替换为通用 Introduction 的规则。
   README 查询不再误召回 `README.i18n.yaml` 等配置文件；显式查询该配置时仍可读取。
4. BM25 缓存绑定实际候选语料 ID 的摘要，避免同一知识版本下切换 README 文件时复用错误语料。
5. 提示词区分组成、参数、依赖与外围组件，要求不凭记忆补代码导入。
   提示词版本为 `knowledge-v3`，最终检索版本为 `hybrid-rrf-cross-encoder-v3`；
   配置及版本变化隔离旧答案缓存，不需要重建向量库。
6. LLM 结构化输出按 Pydantic schema 校验：空值、解析错误或无效结构最多尝试两次，
   仍失败则明确报告 `llm: invalid_structured_output`。网络 / 权限等供应商错误不改写成无结果。
   意外 CLI 错误只附文件名、行号、函数名，不打印响应正文、异常原文、代码行或局部变量。
7. 真实闭环另暴露“已召回的词法首位被 Cross-Encoder 降至第 12、排除出 Top 8”的问题。
   最终增加 `HYBRID_HEAD=1`，在原证据配额内保护两路首位，剩余配额按重排结果选择，
   最终按重排分数排序；极小多仓库配额优先词法首位。设为 0 可做纯重排对照。
   不因此认定任何首位材料可信，充分性判断与引用约束仍照常执行。

主 README 选择是文件族策略，不是译本语义等价证明；译本可能有独有内容。
涉及这类内容时应显式指定文件或关闭该策略。最大候选更多也会增加 CPU 重排成本。

## 真实失败与边界

`data/acceptance/2026-11-05-rerank-v2-web/` 保留首轮失败：
完整 E2E **1 failed，321.53 秒**。官方页面入库、幂等、本地回答、缓存、上下文和不足分支通过；
联网阶段保存资料后 CLI 报 `AttributeError`，未执行后续新会话复用 / PTY。
同一失败库上的一次 local-only 复查没有重现异常，因此**尚未确证原始根因**。
新增返回契约校验和脱敏位置记录是防御性增强，不能据此反推这次失败必由空模型响应造成。
首轮失败没有覆盖、删除或计为通过，重跑使用全新隔离目录。

原六题的跨项目简介仍有严格字面标签漏召回；模型认为“充分”不是人工质量结论。
同模型裁判、小样本、生成随机性、不同时间批次均限制对比解释；
同时修改检索与提示词，不把改善归因于单个组件，也不声称彻底防止幻觉。
多个真实验收进程部分并行，耗时只能作为观测值，不作严格性能基准。
